# 변환한 글 저장과 저장한 글 목록

## 연결된 자료

- 결정 계약: [saved-articles](../../decisions/saved-articles.md) — 저장 사본, 소유자 전용 접근, 비로그인 저장 흐름을 정합니다.
- 결정 계약: [url-to-markdown](../../decisions/url-to-markdown.md) — 변환 방식과 "프롬프트는 저장하지 않는다"를 정합니다.
- 결정 계약: [ui-composition](../../decisions/ui-composition.md) — 새 화면의 구성과 loading·empty·error 상태를 정합니다.
- 용어: [GLOSSARY.md](../../../GLOSSARY.md) — 변환 결과, 저장한 글, 저장한 글 목록.

## 사용자에게 달라지는 점

- 변환 결과 아래에 '저장' 버튼이 생깁니다. 저장하면 그 글이 내 계정에 남습니다.
- 로그인한 사용자는 '저장한 글 목록' 화면에서 지금까지 저장한 글을 최신순으로 보고, 하나를 열어 변환 당시의 본문을 다시 읽을 수 있습니다.
- 로그인하지 않은 사용자가 저장을 누르면 로그인 화면으로 이동하고, 로그인하면 홈으로 돌아와 방금 변환한 글이 자동으로 저장됩니다.
- 홈 화면에서 저장한 글 목록으로 가는 길이 생깁니다. 로그인하지 않았다면 같은 자리에 로그인으로 가는 길이 보입니다.

## 승인된 범위

- 변환 결과 저장(제목, 작성자, 사이트, 단어 수, Markdown 본문, 원본 URL, 저장 시각).
- 저장한 글 목록 화면과 저장한 글 하나를 여는 화면.
- 저장한 글을 열었을 때 기존 변환 결과와 같은 모습으로 본문을 보여 주고, 기존 ChatGPT·Claude 내보내기도 같은 방식으로 쓸 수 있게 하는 것.
- 비로그인 저장 시 결과 보존 → 로그인 → 자동 저장 흐름.

## 수용 기준

1. 로그인한 상태에서 URL을 변환하고 '저장'을 누르면 성공 표시가 나오고, 저장한 글 목록 맨 위에 그 글이 보인다.
2. 저장한 글 목록의 각 항목에는 제목, 사이트(또는 작성자), 저장 시각이 보이고, 최신 저장이 위에 온다. 제목이 없으면 "제목 없음"으로 보인다.
3. 목록의 항목을 열면 저장 당시의 제목·메타·본문이 변환 직후 화면과 같은 모습으로 보이고, 원본 URL로 가는 링크가 있다. 이때 원본 페이지를 다시 가져오지 않는다.
4. 같은 URL을 두 번 저장하면 항목이 두 개 생긴다. 오류는 없다.
5. 저장한 글이 하나도 없으면 목록은 빈 상태 안내와 홈으로 가는 길을 보여 준다.
6. 사용자 A가 저장한 글은 사용자 B의 목록에 나오지 않고, B가 A의 글 주소를 직접 열어도 내용이 보이지 않는다(없는 글과 같은 응답).
7. 로그인하지 않은 상태에서 저장한 글 목록이나 글 주소를 열면 로그인 화면으로 이동하고, 로그인하면 원래 열려던 화면으로 돌아온다.
8. 로그인하지 않은 상태에서 변환 후 '저장'을 누르면 로그인 화면으로 이동한다. 로그인(또는 가입)에 성공해 홈으로 돌아오면 그 변환 결과가 화면에 다시 보이고, 자동으로 저장되며, 저장됐다는 표시가 나온다. 이때 결과를 다시 변환할 필요가 없다.
9. 8번의 왕복 중 보존한 결과가 사라졌더라도(탭을 닫음 등) 로그인은 정상 완료되고 오류 표시는 없다. 저장은 일어나지 않는다.
10. 저장에 실패하면(네트워크, 저장소 오류) 오류 표시가 나오고 변환 결과는 화면에 그대로 남아 다시 저장할 수 있다. 8번 흐름에서 자동 저장이 실패해도 같다.
11. 저장 중에는 저장 버튼이 비활성화되어 연속 클릭으로 같은 글이 여러 번 저장되지 않는다. 한 번 저장한 변환 결과는 같은 화면에서 '저장됨'으로 보이고 다시 저장되지 않는다.
12. 목록과 글 화면은 좁은 화면에서도 내용과 동작이 숨지 않는다. 저장 목록에는 loading 상태가 있다.
13. 프롬프트(직접 입력 포함)는 어디에도 저장되지 않는다.

## 확정된 제약과 이유

- 저장은 저장 시점의 사본이다. 원본이 바뀌거나 사라져도 저장한 글은 그대로다. (근거: saved-articles 계약)
- 저장한 글은 소유자만 읽고 쓴다. 기존 profiles의 소유자 전용 방식과 같은 원칙이다.
- 홈 화면의 변환은 로그인 없이 계속 쓴다. 로그인은 저장할 때만 요구한다.
- 저장 버튼은 명시적으로 누를 때만 저장한다. 변환만으로는 자동 저장하지 않는다. (비로그인 후 자동 저장은 사용자가 저장을 누른 의사가 이어지는 경우에만 해당)
- 새 화면은 ui-composition 계약의 shell, shadcn 구성, 상태 설계를 따른다.
- 이 앱은 강의용 학습 템플릿이다. 동작하는 흐름이 우선이며, 스펙이 요구하지 않은 보안 하드닝과 성능 방어는 범위 밖이다.

## 가정(사용자가 바꿀 수 있는 기본값)

- 같은 URL을 여러 번 저장하면 각각 별도 항목이다(중복 방지 없음). 기준: 사본이라 시점마다 내용이 다를 수 있다.
- 목록은 최신순 단일 목록이다. 검색, 정렬 변경, 페이지 나누기는 없다.
- 보존한 결과는 같은 브라우저 탭 안에서만 유지된다. 가입 확인 메일처럼 다른 탭이나 기기를 거치면 사라질 수 있다. 현재 설정은 가입 즉시 로그인되지만 호스팅 설정이 다르면 이 경우가 생길 수 있다.
- 홈 화면의 진입 링크는 기존 헤더 영역(테마 토글 옆)에 둔다.
- 본문 길이 제한은 두지 않는다. 변환기가 돌려주는 본문 전체를 저장한다.

## 범위 밖과 이유

- 저장한 글 삭제와 수정: 요청에 없다. 아래 보류 항목 참고.
- 저장한 글 공유, 폴더·태그, 검색: 요청에 없다.
- 프롬프트 저장: url-to-markdown 결정이 막는다.
- 비로그인 사용자의 기기 내 저장: saved-articles 결정에서 채택하지 않았다.

## 보류한 항목

- **저장한 글 삭제**: 사용자가 요청하지 않아 이번에 만들지 않는다. 목록에서 지울 수 없어 불편하다는 반응이 나오면 다시 연다. 되살리는 조건: 사용자가 삭제를 요청하거나 저장한 글이 쌓여 목록 정리가 필요해질 때. 이슈 ID는 아직 없다.

## 남은 위험

- 로그인 왕복 중 결과 보존이 브라우저 설정(저장소 차단 등)에 따라 실패할 수 있다. 그 경우 9번처럼 조용히 저장 없이 끝난다.
- 현재 변환 응답에는 원본 URL이 없다. 저장하려면 원본 URL을 결과와 함께 알아야 하며, 이것이 빠지면 3번 기준을 충족하지 못한다.
- 본문이 매우 긴 글(수만 자)도 저장 대상이다. 저장소 한도에 걸리면 10번의 오류 표시로 처리된다.
