How we cut our monorepo build times by 62% with incremental compilation

Dana Whitfield-Okonkwo·engineering.northwind-labs.example·약 1,350단어

Why builds got slow

Two years ago a clean build of our monorepo took 11 minutes and 40 seconds. Most of that time was spent recompiling packages that had not changed since the previous commit.

If a package's inputs have not changed, its output should not be recomputed.

What we changed

  • Hashed every package's source files and lockfile entries.
  • Stored compiled output in a shared remote cache, keyed by that hash.
  • Ran only the affected packages in CI.
$ turbo run build --filter=...[origin/main]
• Packages in scope: web, ui, api-client
• Cache hit rate: 87.3% (41/47 tasks)

Results

Median CI time fell from 11m 40s to 4m 25s. See the full benchmark spreadsheet for per-package numbers.

What we would do differently

We underestimated how much non-deterministic output (timestamps, absolute paths) poisons cache keys. Fixing those took longer than the caching itself.
